## 2026-11-06 / 手柄长按修复与键位页分离

用户反馈：手柄按钮长按会被识别成连续快速的连点，其他手柄操控也没有生效。

### 根因

`GamepadPad` 让标准映射手柄和未识别手柄共用同一个“已按下”集合。每帧先处理标准映射，
再处理原始索引；第二趟的当前状态里没有标准绑定，于是把刚按下的标准绑定当成释放，
下一帧又重新按下。结果所有标准手柄按键与摇杆方向都以帧率反复按下/释放：
动作键表现为连点，方向和抓取在 60 Hz 采样时总是已释放，所以“其他操控无效”。

修复：两类设备各自维护独立集合，释放只作用于本类设备；失焦、关闭手柄、重新扫描与
离开世界时统一释放全部。新增“同帧标准 + 原始两趟、跨多帧长按只产生一次按下”、
“两族互不释放”等回归测试。

### 键位页分离

- 键盘/鼠标与手柄各自四个槽位，分别保存为 `bindings` 与 `controllerBindings`；
  冲突与保留键只在同一设备族内比较，键盘 A 与手柄 A 不再互相干扰。
- 设置页「键盘 / 鼠标」只显示键盘绑定和抓取模式；「手柄」页显示手柄绑定、启用开关、
  死区滑杆、重新扫描、设备与当前按下状态，并只录入手柄按钮。两页的“恢复默认”只重置
  本组键位，无法把一个设备族的输入误存进另一族。
- 配置升级到版本 3：版本 2 的混合四槽按设备前缀拆分到两组（保持各自顺序，四键盘键位
  不丢失）；版本 1 保留键盘并把手柄默认值放入手柄组。旧文件读取后原子写回。

### 验证

`gradlew test`：112 项通过、0 失败。新增长按跨帧、设备族隔离、混合槽拆分和分组默认值测试。
`gradlew build --offline` 通过后替换隔离实例中的旧包；本机仍无实体手柄，实际手感需用户确认。

## 2026-11-06 / 原生手柄操控

新增基于 GLFW 的手柄输入，与键盘、鼠标共用同一条 60 Hz 输入时间线和同一套多键位、
冲突与保留键规则；不引入第三方控制器库。

### 输入来源与命名

- 每帧在 `RenderFrameEvent.Pre` 轮询 16 个 GLFW joystick 槽位，只在客户端线程执行。
  `glfwJoystickIsGamepad` 为真时读取标准布局（A/B/X/Y、LB/RB、Back/Start/Guide、L3/R3、
  方向键、双摇杆与扳机），使用设备无关的名字 `gamepad:button:a`、
  `gamepad:axis:leftx:negative`；未识别的设备回退到原始索引 `joystick:button:0`、
  `joystick:axis:2:positive`，设置页可直接录入。
- 边沿经 `PhysicsKeys.device` 注入现有时间线，因此 60 Hz 子步采样、每动作多槽位、
  抓取模式、失焦清空与 R/Tab 即时切换的行为和键盘完全一致。
- 摇杆按死区转换为数字方向，按下与释放阈值不同（释放 = 死区 × 0.7），避免阈值附近抖动。
  扳机释放时 GLFW 报告 -1，负方向被禁用，只保留正向行程。
- 多个标准手柄合并为同一逻辑设备，未识别手柄按索引合并；热插拔每帧自动检测。
  失焦、关闭手柄输入、重新扫描和离开世界时释放全部已按下边沿；重新获得焦点后先静默
  同步一帧，避免把一直按住的按钮当成新按下。

### 绑定与界面

- 每个动作从 3 个键位扩展到 4 个，可混用键盘、鼠标与手柄。手柄默认：左摇杆/方向键移动、
  A 跳跃、X 冲刺、RT 抓墙、Start 进出横版模式、LB 顺转平面；原键盘默认不变。
- 旧版本 1 配置只在空槽位补入手柄默认值，不覆盖任何已有键盘/鼠标选择，随后原子写入版本 2。
- 设置页新增「手柄」分页：启用开关、摇杆死区滑杆（5%–90%，默认 30%）、重新扫描、
  设备名与映射状态、当前按下的绑定。控制页选中槽位后直接按下手柄按钮即可录入，
  手柄与键盘/鼠标共用冲突与保留键检查。
- 手柄输入只驱动横版模式的运动动作和 R/Tab 快捷操作；原版模式的行走、视角以及背包、
  聊天、菜单导航仍使用键盘/鼠标，本轮不接管原版 KeyMapping 之外的输入路径。

### 验证

`gradlew test`：107 项通过、0 失败。新增手柄绑定格式、死区与迟滞、扳机静止、
断开释放、原始轴命名、版本 1 迁移和默认槽位测试。
`gradlew build --offline` 通过，产物 `build/libs/stevetomadeline-0.1.0.jar` 已替换隔离实例
`mods` 中的旧包。本机没有连接实体手柄，仅确认 GLFW 原生库可加载、设备枚举循环正常；
实际按键映射与手感仍需用户实机确认。

## 2026-11-05 / 连续景深与保守地形裁切

### 变化

旧 `LAYERED` 方案把同一座山沿深度分给两个相机，前后层跟随速度不同；仅增大远景
正交半高仍会在分界处产生尺度跳变。因此新增 `DEPTH` 模式，整片世界使用同一透视投影，
不再在玩家后方设置硬远裁剪面，不再给山体上半部分施加独立滞后，也无需第二趟 WindowX 渲染。
旧离屏分层仍保留，可用 `parallaxMode = "LAYERED"` 切回。

玩家平面的缩放继续由 `orthoHalfHeight` 决定。实际摄像机距离
`D = max(cameraDistance, depthDistance)`，投影视角为 `2 * atan(orthoHalfHeight / D)`。
玩家后方 `d` 格物体的相对尺寸连续变化为 `D / (D + d)`；默认 D=32，后方 32 格处为一半，
后方 96 格处为四分之一。玩家和碰撞坐标不变，远景不会被固定锚点拉开；CPU 剔除包围整个
透视体积，并继续使用能直接包含相机 8 格立方体的安全视锥。

### 推荐配置

```toml
layeredParallax = true
cameraFov = 0.0
parallaxMode = "DEPTH"
depthDistance = 32.0
terrainClipping = "ADAPTIVE"
```

- `DEPTH` 是新配置默认值；已有 `layeredParallax` 开关仍保持用户原值。
- `depthDistance` 越小，远景缩小越明显；不会改变玩家平面的尺寸。
- `parallaxRatio` 仅旧 `LAYERED` 模式使用，新模式由实际深度自然产生视差。
- `terrainClipping = "SLICE"` 强制保留旧式前景切片；`"NONE"` 关闭前景切片。
  关闭时不再叠加平面方块贴图，建筑按原网格绘制，但遮挡玩家的前景也会保留。

### ADAPTIVE 的算法与边界

这是**保守的区域地形候选识别**，不是可靠的建筑语义识别。判断对象是相机与玩家切片之间、
当前画面范围内的一整个前景体积，不会逐方块“只切泥土、自动补全房屋”。只在以下条件
全部满足时，才将该区域作为地形切片：

1. 只有已知自然地形候选材料；未知材料、方块实体或保护标签命中立即保留。
2. 实体积至少 64 格，采样底部覆盖至少 25%。
3. 每个垂直柱必须从采样底部连续实心到表面；浮空、洞穴、屋顶下空腔均保留。
4. 高于两侧且宽度很薄的凸起视作可能的墙/塔，保留。
5. 六面都有同类实心邻居的内部格至少占 35%，避免把薄地板或薄墙当厚地层。

区域未加载或超过 98,304 格采样上限时保留，绝不为判断加载区块。静止时每 5 个游戏 tick
刷新一次，采样区域变化时重新判断；保护结果至少保持 20 tick，减少边界切换抖动。
这不是异步无限扫描，工作量有固定上限。只有确认为地形时才绘制自然材料的切片截面，
保留区域不覆盖平面贴图。

**不能保证的情况**：玩家用原石、泥土等自然材料堆成的厚实建筑，若材料与空间分布都和山体
相同，无法从当前方块状态判断来源，仍可能被裁。反过来，带树木/水/建筑的混合区域、天然洞穴、
窄山脊等会倾向于全部保留，可能多留地形甚至遮住玩家。它优先降低误裁建筑的风险，
不是对所有地图都准确的“优秀分类器”。这些场景应手动选择 `NONE` 或 `SLICE`。

数据包可扩展 `stevetomadeline:terrain_candidates` 与 `stevetomadeline:protected_foreground`
两个方块标签（`data/stevetomadeline/tags/block/*.json`），保护标签优先；候选标签仅提供材料证据，
不会跳过几何判断。标签按方块类型作用于所有位置，不是单栋建筑的区域标注。

### 验证状态

新增 `DepthProjectionTest`、`TerrainClassifierTest` 源码，覆盖玩家尺度、远景比例、剔除范围、
厚地层、坡面、细墙、空腔、混合材料及不可区分的实心天然材料建筑。

## 2026-11-05 / 开启分层视差后未响应修复

用户反馈：开启分层视差后游戏未响应。实例 `latest.log` 最后记录为
`[STM] layered parallax active: ratio=0.4, target=1280x681`，未留下异常堆栈，
说明第一张 WindowX 远景纹理已成功发布，故障发生在主画面开始使用它之后。

源码核对发现：`GameRenderer.getProjectionMatrix` 的返回值同时用于绘制和
`LevelRenderer.prepareCullFrustum`。纹理就绪后近/远面默认变为 7/9，只有 2 格厚；
原版 `Frustum.offsetToFullyIncludeCameraCube(8)` 却不断平移视锥，直到完整容纳相机所在
8 格网格立方体。正交体积不会随平移变宽，因此这个循环无法结束。即使不启用视差，
过小的正交半高或窗口宽高比也存在类似问题。

修复：在调用 `prepareCullFrustum` 时单独提供 `CameraCulling.orthographic`，
只扩大 CPU 剔除范围，不改变 GPU 绘制的切片厚度或远景分层。剔除范围至少覆盖相机
各方向 16 格（大于 8 格立方体任意角点距离 `sqrt(3) * 8`），并保留正常远平面，
使相机立方体无需平移就已包含。原版、透视模式以及其他 WindowX 相机保持原路径。

新增 `CameraCullingTest` 源码，覆盖日志中的坐标、四朝向、12° 下俯、窄窗口、
最小/最大缩放、绘制范围包含关系及旧 2 格切片的反例；按用户要求不运行测试或启动游戏。
没有卡死时的线程转储，实际游戏恢复情况仍由用户确认。

- `parallaxRatio` 仅作用于屏幕水平方向，默认 0.4；高度和深度轴完全跟随。
  按相对锚点的位置计算，停止移动不会回弹，不依赖帧率。偏移连续限制在 32 格，
  达到上限后随主相机移动；单帧位移超过 48 格、朝向或比例变化会重建锚点。
- R 切换、关闭配置、退出世界会释放 binding 与双缓冲；换维度按世界实例重建。
  所有主相机/切片钩子都避开其他 WindowX 相机，合成恢复投影、着色器与深度/混合状态。

### 版本边界

WindowX 2.2.0-Beta2 没有公开查询 binding 纹理的 API；使用 `WindowXRenderAccess`
读取注册表并调用其销毁函数，`WindowXRenderMixin` 只在 `publish` 成功后的 `updateWin`
记录帧就绪。无窗口 binding 不能通过 WindowX 的原生窗口过滤删除，因此按本模组唯一 ID
精确移除。升级锁定依赖时须重新核对这两个接口和 `AFTER_LEVEL` 调度。

## 2026-11-05 / P0 技术验证（主窗口正交摄像机 + 2D 渲染）

### 目标

按 `初版开发计划书.txt` 的 P0：在真实 Minecraft 1.21.1 世界中接管主窗口摄像机，
实现正交侧视与可玩的 2D/2.5D 观感，为 P1（R/Tab 平面切换）打基础。

代理地址属于开发环境，不写入仓库。

### 结论先行

1. **主窗口接管可行**：`Camera.setup` + `GameRenderer.getProjectionMatrix` 两个 mixin 即可把主窗口
   换成侧视正交摄像机；不需要 WindowX 的独立窗口。
2. **WindowX 正交语义**：`CameraOptions.fov` 在 ORTHOGRAPHIC 下是**正交半高（方块）**，
   直接写进 `Matrix4f.ortho(-w, w, -h, h, 0.05, far)`。我们已把该语义沿用到主窗口投影。
3. **WindowX 会清天空像素**：`CameraSkyMask` 用深度纹理把“远平面”像素 alpha 置 0。
   自定义叠加层若不写深度会被整体抹掉——这是早期 2D 全黑的根因之一。
4. **两趟渲染不可在关卡渲染中途执行**：在 `RenderLevelStageEvent` 里递归调用
   `LevelRenderer.renderLevel` 会让游戏卡死（未响应）。原分层方案曾因此挂起，现已替换为上节方案。

### 当前实现

**模式**：R 键循环。默认 `原版 ↔ 2D`；`enableIsometric = true` 时加入 2.5D 彩蛋。

**摄像机（两种模式共用）**
- `CameraMixin`：每帧 TAIL 写入我们的位姿；`detached = true` 强制玩家模型渲染。
- `CameraController`：侧视方向吸附 90°；2.5D 下俯 12° 并沿视线做方块检测防埋入。
- `GameRendererMixin`：返回正交投影；2D 下近平面 = `distance - sliceHalfThickness`，
  切掉相机与玩家之间的方块；2.5D 近平面 0.05。
- 摄像机模式取消手持物品（`RenderHandEvent`）、准星（`RenderGuiLayerEvent`）、视角摇晃（`bobView`）。

**2D 渲染（方案 A）**
- 背景：普通正交世界渲染，原版天空盒/昼夜保留；雾由 `RenderFog` 接管，默认 96→448 格，
  雾色固定为当前天空色（入水不再变色）。
- 前景：`CameraRenderHandler` 在 `AFTER_TRANSLUCENT_BLOCKS` 于玩家所在轴绘制
  **方块朝向相机的那一面**的贴图（`BakedModel.getQuads`），空气格留空透出背景；
  光照 = `max(方块光, 天光 × 太阳系数)`，环境底光 0.35（泰拉瑞亚式）。
- 实体只保留与平面距离 ≤ `sliceHalfThickness` 的。

**2.5D（彩蛋）**
- 侧视正交 + 下俯 12° + 抬高相机；普通 3D 世界渲染；默认关闭。

### 配置（`config/stevetomadeline-client.toml`）

| 键 | 默认 | 说明 |
|---|---|---|
| `cameraDistance` | 8.0 | 相机水平距离（0.5–128） |
| `orthoHalfHeight` | 10.0 | 正交半高（方块） |
| `sliceHalfThickness` | 1.0 | 2D 切片半厚度 / 实体过滤范围 |
| `fogStart` / `fogEnd` | 96 / 448 | 摄像机模式雾距离 |
| `cameraFov` | 0.0 | >0 时改为透视（实验，非目标方案） |
