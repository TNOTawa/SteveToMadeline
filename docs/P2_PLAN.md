# P2 Celeste 物理开发顺序

依据：`初版开发计划书.txt` 第 2.2、2.3、3、4.2、5、6 节。
用户已确认 P1 实机体验无问题并允许进入 P2。基础代码已接入，待用户测试；具体范围与差异见 `P2_IMPLEMENTATION.md`。

## 保留的基线

- 保留已验收的 R/Tab 交互、水平中心吸附、进入前朝向对应屏幕右侧及可配置选择。
- 保留 Tab 默认 0.3 秒摄像机缓动，以及默认 DEPTH + ADAPTIVE 画面。
- P1 当前沿用原版移动/跳跃，只限制运动平面。P2 要接管运动计算，不能把新物理简单叠加
  在原版重力、摩擦和跳跃上，也不能在渲染帧里改变游戏物理。
- 物理状态与平面状态分开：`PlaneState` 继续描述方向和锚点，`core.physics` 描述速度、
  接触、动作、计时器、冲刺次数和体力；通过 P1 的轴映射与生命周期集成。
- 玛德琳、头发和资源加载留在 P3。用户随后取消 P4 外部键位导入，P2 改用原版控制界面
  注册可重绑定并持久化的移动/跳跃/冲刺/抓墙按键，以及冲刺次数和体力反馈。

## 1. 物理模型、单位与输入语义

建立可独立计算的 `PhysicsState`、参数和输入快照，明确方块、秒、方块/秒和方块/秒平方。
规划普通/冲刺/攀爬等状态和转换条件，把按下、持续按住、松开分开；一次按下只能消费一次，
不能因为每 tick 有三个子步而触发三次跳跃或冲刺。

后续规格明确 16 Celeste px = 1 格；站立碰撞箱 X/Y/Z = 0.5/0.6875/0.5，
蹲姿及 Demo Dash 为 0.5/0.375/0.5；站立受伤判定高度 0.5625 格、蹲姿 0.25 格。
脚底与水平中心保持不变。速度等参数仍使用明确的方块/秒单位，碰撞/受伤分离。

## 2. 固定步长与 Minecraft 碰撞接管

每个正常 20Hz 逻辑 tick 执行三个 1/60 秒子步，输入序列与子步编号明确对应。
每个子步将平面位移映射到世界坐标，交由 Minecraft 的三维 AABB/方块碰撞形状处理，
再根据实际位移更新速度和接地/碰墙/顶头状态；视觉裁切不能改变碰撞世界。

先用最小的重力/落地流程建立接管入口，排除原版与新物理重复积分、重复移动和重复伤害处理。
碰撞检测要覆盖高速位移经过的路径，不能只检测冲刺终点；半砖、楼梯、低天花板与墙角
按实际碰撞形状处理。退出模式必须解除接管，恢复原版行为；手动退出前先检查原版
站立/蹲伏/爬行尺寸，所有姿态都放不下时保留模式并提示，避免原地扩张进方块。

60Hz 指模拟步长，不保证服务器掉速时仍有真实时间 60Hz；不通过无限追赶或把一个子步变长
来补偿卡顿。渲染插值与模拟时钟分开。

## 3. 服务端权威与最低限度客户端预测

从一开始发送带序号的输入，由服务端运行相同物理并确认状态；客户端预测本地输入，
收到确认后纠正并重放未确认输入。位置、速度、动作计时器、冲刺次数和体力一起校正，
不能只修正坐标。暂停、GUI、断连和重新进入模式需要清空失效输入。

区分原版位置包与 P2 物理状态包的职责，避免两套流程相互拉扯。物理参数由服务端提供统一值，
不能继续全部放在纯客户端 Config；相机与键位仍留在客户端。

这是初版第 4.2 节要求的 P2 基础同步；P6 再扩大多人兼容、异常网络和性能验证范围。
单人游戏同样包含客户端和内置服务端，不能推迟到 P6 才解决双端运动权威问题。

## 4. 跑动与完整基础跳跃

顺序：地面加速/减速与转向 → 空中控制 → 普通跳跃 → 松键截断/按住延长的可变跳高
→ 土狼时间 → 跳跃缓冲 → 落地恢复。

第一份可体验的 P2 产物先完成这一组：能稳定跑跳、顶头停止上升、撞墙停止对应方向移动，
按键长短改变跳高，平台边缘和落地前的短输入窗口有效。

## 5. 八方向冲刺与恢复

基于平面方向输入选择八方向，无方向时按角色朝向冲刺；斜向输入归一化，避免更快。
加入冲刺持续时间、退出速度、输入缓冲/冷却、可用次数和落地恢复规则。
高速碰撞沿路径处理；转向、R 反复进入和网络重放不能重复触发或凭空补充冲刺次数。
冲刺不可中断阶段使用 P1 的 turnLocked/pendingTurn，结束后再处理 Tab。

## 6. 墙面接触、贴墙滑行和墙跳

从碰撞结果与必要的短距离探测确定可接触的墙面，不把任意相邻方块都当作整面墙。
先做滑行限速，再做墙跳的离墙横向速度、竖直起跳速度和短暂输入约束。
重点处理左右墙对称、台阶边缘、墙顶和低天花板，不把高阶墙角技巧纳入首轮范围。

## 7. 抓墙、攀爬和体力

接入抓墙输入、停留/上爬/下爬、体力消耗、耗尽脱离与落地恢复；墙跳和冲刺按状态机
切换，明确各动作是否消耗体力。提供基础体力和冲刺可用性反馈，暂不依赖 P3 角色动画。
将抓墙中不可安全执行的 Tab 请求延期，并在脱离墙面或动作结束后重新检查碰撞再转向。

## 8. 与 P1 生命周期统一收口

逐项检查 R 退出、Tab 中心吸附/速度转换、摄像机缓动、配置关闭、死亡、重生、传送和换维度。
P1 的中心吸附是离散操作，不能在每个物理子步执行；转向必须作用于完整物理状态，
不再只修改原版 deltaMovement。清除动作锁、旧计时器、旧输入与预测历史，不能遗留冲刺或攀爬。

沿用已验收的“缓动期间暂缓新横向输入”规则，但明确跳跃、冲刺和待执行转向的优先级，
不能让相机动画成为另一套物理时钟。

## 9. 参数调校与回归交付

随每个动作补回归测试源码，最后统一整理可重复的输入回放与测试关卡清单：

- 同一初态、相同碰撞环境和相同输入序列得到相同模拟结果；切换渲染帧率不改变物理。
- 可变跳高、土狼时间、缓冲窗口及冲刺恢复边界准确，输入不会多次消费。
- 八方向冲刺距离合理，高速不穿过墙/天花板，半砖/楼梯采用真实碰撞形状。
- 两侧墙的滑行、墙跳、体力消耗一致；墙面消失时不会悬空抓墙。
- R/Tab 与死亡/传送不会刷出动作资源或留下锁轴、冲刺和预测状态。
- 四个平面方向体验一致，客户端预测与服务端状态能收敛。

用户现允许代理运行自动测试，但不启动游戏；实机体验仍由用户执行。
每一阶段的编译通过都不等于 P2 行为验收通过。

## 分批体验顺序

1. 固定步长、碰撞和基础同步接入后的跑动/跳跃闭环。
2. 八方向冲刺与次数恢复。
3. 墙面动作、体力和 P1 全生命周期整合。

完成标准仍按初版：基础移动可操作、碰撞稳定、物理测试可重复通过；
不把编译成功或单一动作可用提前当作 P2 完成。
